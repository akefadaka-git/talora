### Release 5 — Professional Expansion
- Advanced import/export compatibility.

- Expanded IROKA capabilities.

## Governance stages

**A1 — Assessment and specification:** Define product, requirements, architecture, risks, assumptions and acceptance criteria.

**A2 — Read-only reconciliation:** Inspect IROKA repositories and interfaces, technical compatibility, dependencies, security, hosting and costs. Do not modify implementation repositories or main branches during this stage.

**A3 — Implementation:** Begin only after explicit Owner authorization defining scope, branch and starting SHA.

**A4 — Verification:** Run reproducible tests, security and performance checks, export validation and acceptance testing against exact SHAs. Remediate authorized scope.

**A5 — Deployment:** Separate approval for signing, store submission, production infrastructure, release and operational activation.

## Delivery evidence

Each implementation report should include:
- Repository, branch and exact SHA.
- Changed files and scope.
- PR and workflow evidence where available.
- Test commands and results.
- Migration status.
- Security and dependency findings.
- PASS, VERIFIED-CLOSED, PARTIAL, MISSING, UNRESOLVED, UNKNOWN or NOT RUN labels.
- Remaining risks and next authorized action.

No stage is closed solely on the basis of a written assertion.
